1. Executive Summary (Resumen Ejecutivo)

La evaluación metodológica de la seguridad informática permite identificar, de manera anticipada, las debilidades y los vectores de ataque presentes en un sistema, antes de que estos puedan ser aprovechados por un actor con intenciones maliciosas. En este sentido, las pruebas de penetración constituyen una metodología ampliamente utilizada para analizar la postura de seguridad de un sistema, pues simulan escenarios reales de ataque con el propósito de detectar debilidades, evaluar su impacto potencial y proponer medidas de mitigación.

En relación con lo anterior, el presente proyecto tiene como objetivo desarrollar un informe técnico de pruebas de penetración (Pentesting Report) sobre la máquina vulnerable My File Server - 1, aplicando una metodología estructurada de evaluación de seguridad. Dicha actividad se llevó a cabo utilizando una máquina virtual con sistema operativo Kali Linux como entorno de ataque, y el host 192.168.56.103 (FILESERVER) como el sistema objetivo. El análisis incluyó la definición del alcance de la prueba, la aplicación de una metodología de pruebas de penetración y el desarrollo de las etapas de la misma, entre ellas las fases de reconocimiento, enumeración, explotación y escalada de privilegios.

Como resultado de la evaluación, se documentaron hallazgos relevantes con evidencias técnicas, un análisis de impacto basado en el modelo de seguridad C.I.A. (Confidencialidad, Integridad y Disponibilidad), y recomendaciones técnicas orientadas al robustecimiento de la seguridad. La cadena de explotación documentada permitió escalar desde un acceso anónimo hasta el control total del sistema (usuario root), por lo que el nivel de riesgo global del activo se considera CRÍTICO.

2. Alcance (Scope)

El presente reporte consiste en la ejecución de una prueba de penetración controlada sobre la máquina objetivo My File Server 1 (192.168.56.103), utilizando como equipo atacante Kali Linux.

  • Incluye: Definición del alcance técnico, reconocimiento y enumeración de servicios (FTP, SMB, HTTP, NFS), explotación controlada y escalada de privilegios.
  • Excluye: Pruebas sobre sistemas ajenos a My File Server 1, ingeniería social, phishing a usuarios y ataques destructivos.
  • Restricciones: Entorno de laboratorio controlado (VulnHub), herramientas de código abierto predeterminadas en Kali Linux.

3. Metodología Aplicada

El análisis se rigió por fases estructuradas de seguridad ofensiva: Reconocimiento, Enumeración, Explotación y Escalada de Privilegios. Herramientas empleadas: arp-scan, Nmap, Nikto, SMBMap, cliente FTP, ssh-keygen, gcc y exploit público CVE-2016-5195 (Dirty COW).

4. Fases de Reconocimiento

Se localizó la máquina objetivo en la red local mediante sudo arp-scan -l, identificando la IP 192.168.56.103. Posteriormente se realizó un escaneo completo de puertos y servicios con Nmap:

5. Enumeración

Mediante el escaneo con Nikto en el puerto 80, se localizó el archivo readme.txt accesible públicamente, el cual revelaba la contraseña en texto plano: rootroot1. Asimismo, el análisis con smbmap confirmó que el recurso compartido smbdata permitía acceso mediante sesión NULL con permisos de lectura y escritura.

6. Explotación

Utilizando las credenciales obtenidas (smbuser / rootroot1) y el servicio FTP habilitado, se generó un par de llaves SSH (ssh-keygen) y se cargó la llave pública en el servidor remoto como .ssh/authorized_keys. Esto permitió acceder vía SSH al servidor sin requerir contraseña:

ssh smbuser@192.168.56.103

7. Escalada de Privilegios

Revisando la versión del kernel con uname -a (Linux fileserver 3.10.0-229.el7.x86_64), se identificó vulnerabilidad a CVE-2016-5195 (Dirty COW). Se descargó el exploit 40616.c, se compiló con gcc y se ejecutó, logrando sobrescribir /usr/bin/passwd y obteniendo una consola con privilegios de root (uid=0(root)).

8. Análisis de Impacto (Modelo C.I.A.)

  • Confidencialidad (Crítico): Divulgación de credenciales en texto plano (readme.txt) y acceso total a archivos del servidor.
  • Integridad (Crítico): Modificación de archivos del sistema operativo mediante Dirty COW (/usr/bin/passwd) y subida de llaves de persistencia.
  • Disponibilidad (Alto): Riesgo de inestabilidad del kernel o interrupción de servicios al manipular binarios críticos del sistema.

9. Recomendaciones Técnicas

Eliminar archivos de prueba (readme.txt), deshabilitar acceso anónimo FTP, restringir permisos de escritura en directorios home, forzar la firma de mensajes SMB, deshabilitar sesiones nulas, actualizar Apache httpd y aplicar los parches correspondientes del kernel para corregir CVE-2016-5195 (Dirty COW).
