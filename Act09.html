Introducción

Nombre del laboratorio: Traversal Sequences Stripped Non-Recursively

Nivel del laboratorio: Practitioner

Tipo de explotación: Es una vulnerabilidad que permite manipular una ruta de archivo proporcionada por el usuario para intentar acceder a archivos que se encuentran fuera del directorio que la aplicación pretendía permitir.

Objetivo del Laboratorio

El objetivo es demostrar cómo una validación incorrecta de las secuencias de traversal puede ser evadida. En este laboratorio, la aplicación intenta eliminar las secuencias ../ de la entrada del usuario. Sin embargo, la eliminación se realiza una sola vez (no recursivamente). Esto permite construir una entrada que, después del primer filtrado, vuelva a contener una secuencia válida de traversal con el propósito de conseguir que la aplicación lea un archivo ubicado fuera del directorio esperado.

Explicación Técnica del Laboratorio

El laboratorio presenta una vulnerabilidad de File Path Traversal debido a que la aplicación permite que un parámetro proporcionado por el usuario influya en la ruta de un archivo que el servidor intenta leer. Para evitar este tipo de ataque, la aplicación elimina las secuencias ../ de la entrada. Sin embargo, el filtro funciona de manera no recursiva, es decir, solo realiza la eliminación una vez. Esto permite utilizar una entrada especialmente construida que, después de pasar por el filtro, vuelva a generar una secuencia ../. De esta manera, es posible evadir la validación y acceder a archivos ubicados fuera del directorio originalmente permitido.

Procedimiento Paso a Paso

Paso 1: Acceso al Laboratorio y Configuración de Burp Suite

Como primer paso debemos ingresar a la página en donde accederemos al laboratorio, para después acceder a Burp Suite y encontrarnos con la ventana de configuración inicial de proyecto temporal en memoria.

Paso 2: Opciones por Defecto del Proyecto

Una vez que accedimos a Burp Suite, nos aparece una ventana para poder iniciar la configuración utilizando la opción por default de proyecto temporal en memoria, damos clic en Siguiente y posteriormente dejamos la configuración default de Burp Suite dando clic en Start Burp.

Paso 3: Navegación a la Pestaña Proxy

Ya que terminamos la configuración de Burp Suite, se nos muestra la página principal del sistema, por lo que ahora debemos movernos a la pestaña de Proxy.

Paso 4: Encendido del Intercept y Apertura del Navegador

Ya estando en la pestaña de Proxy podemos observar que el Intercept está apagado, por lo que debemos encenderlo (Intercept is on) y dar clic en Abrir Navegador (Open browser).

Paso 5: Ingreso de la URL del Laboratorio y Uso de Forward

Al abrir el navegador, ingresamos el enlace del laboratorio. Después nos regresamos a Burp Suite en la pestaña de Proxy y damos clic en Forward hasta encontrar un endpoint de imagen.

Paso 6: Envío a Repeater y Modificación del Endpoint

Seleccionamos la instrucción del endpoint, damos clic derecho y seleccionamos Send to Repeater. Nos movemos a la pestaña del repetidor y modificamos la instrucción escribiendo: GET /image?filename=....//....//....//etc/passwd HTTP/2. Damos clic en Send.

Explicación del Payload

Payload utilizado: ....//....//....//etc/passwd

El payload es la entrada especialmente modificada que se envía a la aplicación para aprovechar la vulnerabilidad. En este laboratorio se utiliza una secuencia de traversal construida de manera que el filtro elimine una parte de ella (las subcadenas ../ internas), pero después de esa única pasada permanezca una secuencia ../ válida. Esto funciona porque el filtro realiza la eliminación una sola vez y no vuelve a revisar el resultado. De esta forma, el payload consigue modificar la ruta que procesa el servidor y permite solicitar un archivo ubicado fuera del directorio originalmente permitido.

Mitigación Recomendada

1. Normalización y canonicalización de rutas

Normalizar y canonicalizar la ruta antes de utilizarla, asegurándose de validar que la ruta resultante permanezca estrictamente dentro del directorio permitido.

2. Listas blancas y control de acceso

Utilizar una lista de archivos permitidos (allowlist) cuando sea posible, evitando que el usuario controle directamente rutas del sistema de archivos y aplicando controles de acceso rigurosos del lado del servidor.
