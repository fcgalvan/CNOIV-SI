Introducción

Nombre del laboratorio: File Path Traversal: Validation of File Extension with Null Byte Bypass

Nivel del Laboratorio: Practitioner

Tipo de explotación: Path Traversal (Directory Traversal) con bypass mediante Null Byte (%00). La vulnerabilidad permite manipular el nombre de un archivo solicitado para acceder a archivos fuera del directorio permitido.

Objetivo del Laboratorio

El objetivo es obtener el contenido del archivo /etc/passwd aprovechando una vulnerabilidad de Path Traversal en la funcionalidad que muestra las imágenes de los productos. La aplicación intenta impedir el acceso a archivos que no tengan la extensión esperada, pero su validación puede ser evadida mediante un Null Byte.

Explicación Técnica de la Explotación

La aplicación recibe mediante un parámetro el nombre de la imagen que debe mostrar. Antes de procesarlo, comprueba que el nombre termine con una extensión determinada, por ejemplo .jpg. El problema aparece cuando se introduce un Null Byte (%00) dentro del nombre del archivo.

  1. El payload puede seguir una estructura como: ../../../../etc/passwd%00.jpg.
  2. La validación puede interpretar que el nombre termina en .jpg, por lo que considera que el archivo es válido.
  3. Posteriormente, dependiendo de cómo el servidor procese la cadena, el %00 puede actuar como terminador de la cadena y hacer que la extensión agregada después sea ignorada.
  4. De esta manera, la aplicación puede terminar intentando acceder realmente a: /etc/passwd en lugar de una imagen.

Explotación

Primero se identifica la petición utilizada para cargar una imagen de producto. Por ejemplo, podría tener una estructura similar a: /image?filename=.... Se modifica el parámetro filename utilizando traversal ../../../../etc/passwd%00.jpg y el Null Byte. La cantidad de ../ necesaria depende de la ubicación del directorio desde el cual la aplicación intenta cargar las imágenes. El objetivo final es conseguir que la respuesta HTTP muestre el contenido de: /etc/passwd.

Procedimiento Paso a Paso

Paso 1: Acceso a la página y Burp Suite

Primero deberemos acceder a la página en donde podremos ingresar a nuestra práctica de laboratorio. Después de haber ingresado, debemos iniciar Burp Suite, que es en donde estaremos realizando la práctica. Continuando, una vez iniciado Burp Suite, debemos de movernos a la pestaña de Proxy.

Paso 2: Activación del Intercept en Proxy

Una vez en la pestaña de Proxy, podemos ver que el Intercept está apagado, por lo que debemos encenderlo, para así dar clic en Open Browser.

Paso 3: Ingreso del enlace de la práctica y Forward

Una vez abierto el navegador deberemos ingresar el enlace de la práctica. Ya que ingresamos el enlace, nos moveremos a la ventana de Burp Suite, en donde veremos todas las acciones que se llegan hacer para que la página cargue. Para poder realizar la práctica debemos de dar clic en Forward hasta que en las peticiones nos aparezca la ruta de una imagen.

Paso 4: Envío a Repeater

Ya que ubicamos el endpoint, debemos seleccionarlo y dar clic derecho sobre lo seleccionado, para que se nos despliegue un menú en el cual se mostrarán diferentes opciones, nosotros en este caso seleccionaremos la opción de Send to Repeater (Enviar al Repetidor).

Paso 5: Modificación con Null Byte

Después de haber mandado esta instrucción al repetidor, debemos movernos a la pestaña de Repeater, en donde cambiaremos la ruta para que se pueda abrir la imagen. Ahora procederemos a modificar el payload, lo cambiaremos por lo siguiente: GET /image?filename=../../../../etc/passwd%00.jpg y damos clic en Send.

Paso 6: Verificación de Resultados

Una vez que dimos clic en Send, se deberá mostrar el contenido del directorio en el apartado de Response. Al poder observar esta información, esto nos indica que nuestra práctica está terminada de manera satisfactoria. Para confirmar que nuestra práctica ya está completa debemos irnos a la página de la práctica, en donde se deberá ver que ya está completada.

Explicación del Payload

El payload utilizado es: ../../../../etc/passwd%00.jpg

Se puede dividir de esta manera:

  • ../../../../: Intenta salir del directorio donde se encuentran las imágenes.
  • etc/passwd: Especifica el archivo que se intenta obtener.
  • %00: Representa un Null Byte codificado.
  • .jpg: Busca satisfacer la validación que exige una extensión de imagen.

La parte más importante es: %00.jpg. La aplicación puede comprobar la cadena completa y detectar jpg, pero una función posterior de procesamiento de archivos puede interpretar el Null Byte como el final de la cadena. Esto permite que la validación y el procesamiento del archivo tengan comportamientos diferentes.

Mitigación Recomendada

La principal medida es no confiar en la entrada proporcionada por el usuario y evitar que el usuario controle directamente las rutas de archivos. Se recomienda:

  1. Resolver la ruta mediante funciones seguras y comprobar que la ruta resultante permanezca dentro del directorio autorizado.
  2. No confiar únicamente en comprobar extensiones como .jpg, .png, etc.
  3. Rechazar caracteres y secuencias utilizadas para traversal, como ../, aunque esto por sí solo no debe considerarse una defensa suficiente.
  4. Manejar correctamente los Null Bytes y realizar la validación sobre la cadena que realmente será utilizada para acceder al archivo.
  5. Aplicar permisos mínimos al usuario con el que se ejecuta la aplicación para limitar el impacto de una posible vulnerabilidad.
