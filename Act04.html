Act. 04: Una página demasiado convincente
Simulación de Phishing y Credential Harvester

🎯 Objetivo de la Actividad

El objetivo de esta actividad, más allá de saber cómo "hacer phishing", es comprender cómo funciona para poder defendernos en caso de que se llegue a presentar una situación como esta. Permite entender de manera más profunda cómo se realizan las capturas de datos desde una página que parece legítima. Gracias a esta práctica, en un futuro sabremos identificar de mejor manera el phishing debido a que ya conocemos su construcción.

💻 Descripción del Escenario

En este caso se desarrolló una página simulando el inicio de sesión de una institución educativa para demostrar el comportamiento al autenticarse en este tipo de plataformas. Inicialmente se creó una carpeta llamada laboratorio_portal, donde se redactó el código HTML para estructurar el formulario web.

Posteriormente, dentro de la terminal y ubicados en la misma carpeta, se ejecutó el servidor local con el comando python3 -m http.server 8000 utilizando el puerto 8000, ideal para trabajos locales. Asimismo, se implementó un script auxiliar llamado servidor.py para visualizar el funcionamiento de la página y resguardar las credenciales ingresadas.

🔍 Configuración del Social-Engineer Toolkit (SET)

Se configuró el Social-Engineer Toolkit (SET), un conjunto de herramientas de código abierto basado en Python que automatiza pruebas de penetración enfocadas en la ingeniería social (técnica de manipulación psicológica para provocar errores humanos y comprometer la seguridad). Los pasos seguidos fueron:

  • Selección de la opción 1: Social-Engineering Attacks.
  • Selección de la opción 2: Website Attack Vectors.
  • Selección de la opción 3: Credential Harvester Attack Method (técnica para recolectar nombres de usuario, correos y contraseñas sin consentimiento).
  • Selección de la opción de clonación o importación de la carpeta del sitio web y configuración de la dirección IP de bucle local 127.0.0.1 (comunicación exclusiva en la máquina virtual sin conexión exterior).

🛡️ Controles de Seguridad Propuestos

Desconfía de correos no solicitados

Elimínalos directamente y bloquea al remitente.

No respondas ni compartas información

Nunca envíes datos personales, credenciales o información bancaria por estos medios.

Verifica los remitentes y enlaces

Comprueba la autenticidad antes de hacer clic o proporcionar datos confidenciales.

Evita descargas sospechosas

No abras archivos adjuntos de origen dudoso que puedan contener malware.

Mantén sistemas actualizados

Usa software de seguridad (antivirus) y mantén tus dispositivos al día.

Activa la Autenticación de Doble Factor (2FA)

Configúrala siempre que esté disponible para añadir una capa extra de protección.

📌 Conclusión

El desarrollo de esta práctica permitió comprender de manera práctica el funcionamiento de los ataques de ingeniería social, específicamente el uso de herramientas automatizadas como el Social-Engineer Toolkit (SET) combinadas con interfaces web personalizadas para la recolección de credenciales (Credential Harvester). A través del despliegue en un entorno local y controlado (127.0.0.1), se evidenció la vulnerabilidad fundamental a la que se enfrentan los usuarios ante la suplantación de identidad visual y la falta de verificación en las plataformas de autenticación.

Asimismo, se constató que la concientización humana y la adopción de medidas técnicas avanzadas son indispensables. Depender exclusivamente de la precaución del usuario es insuficiente, por lo que la implementación de controles de seguridad robustos —tales como la autenticación multifactor (MFA) resistente a phishing, protocolos estrictos de validación de correo y una cultura continua de ciberseguridad— resulta crucial para mitigar eficazmente estos vectores de ataque y proteger los activos de información institucionales.
